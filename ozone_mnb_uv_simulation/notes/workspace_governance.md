# 项目工作区与 DFT 平台边界

## 路径边界

- **DFT 系统根目录**：`E:\dft-service`
- **本项目总目录**：`E:\dft-service\ozone_mnb_uv_simulation`

本项目目录用于保存与“臭氧微纳米气泡—紫外协同模拟”直接相关的模型、输入、运行产物、整理结果和研究记录。它不属于 DFT 平台源码的日常改动范围。

## 文件归属

| 类别 | 项目内位置 | 用途 |
| --- | --- | --- |
| 模拟文件 | `models/`、`inputs/`、`jobs/`、`protocols/`、`run_artifacts/` | 模型结构、输入、任务脚本、方法配置及原始运行产物 |
| 结果文件 | `results/` | 经质量检查、可用于解释实验的结构、能量、频率、表格和图 |
| 研究说明 | `notes/`、`templates/` | 假设、实验对应、质量审查和计算记录模板 |
| DFT 平台源码 | `E:\dft-service\dft_service\`、`scripts/`、入口脚本、依赖与测试文件 | 默认只读，不存放本项目数据 |

## 文件与修改边界

- 本批产生的模型、输入、作业脚本、原始输出和结果，只能写入 `E:\dft-service\ozone_mnb_uv_simulation\` 下对应目录。
- 不得修改 `E:\dft-service\` 下的 `dft_service/`、`scripts/`、入口脚本、依赖文件或测试文件。
- 只有确认问题可由独立最小案例稳定复现、且根因位于 DFT 平台源码或平台配置时，才允许修复平台。
- 平台修复前必须记录：复现命令、根因、影响范围、最小修复方案；修复后必须运行对应回归测试，并在本项目 `notes/` 中记录平台版本和修复摘要。
- 不能确认是平台根因的问题，一律在项目工作区内调整模型、输入或任务配置，不改 DFT 系统。

## Claude Code 执行要求

每一条计算指令必须列明：当前研究阶段、已完成内容、本批目标、文件写入范围、验收标准及后续待完成内容。执行者应先遵循本文档，再进行任何文件修改或计算。

每批开始前还须阅读[研究方向与当前进度](../PROJECT_STATUS.md)。批次交付或重要结论修订后，同步其最新状态、成果限定与下一步目标，并在长期记忆中引用该文件。保留旧批次证据；不得把诊断批次数、脚本修复次数或未验收结果当作反应机理成果。总进度更新不替代具体计算批令的预算与授权。
